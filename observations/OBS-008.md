# OBS-008 — UTF-8 BOM is rejected at source start

Category: COMPILER / LEXER / WINDOWS
Status: CONFIRMED + MITIGATED

## Source

    main() {
        println("Hello, Kof!")
    }

## Attempt 1

The source was created as UTF-8 containing a BOM.

Result:

    hello.kf:1:1: error: Unexpected character: '﻿' [LEX005]

The actual Kof source tokens were therefore not accepted before the
leading BOM was processed.

## Attempt 2

The source content was kept identical.

Only the BOM was removed by writing the file as UTF-8 without BOM.

Result:

    Hello, Kof!

## Conclusion

Kof 0.0.7-alpha at the frozen EXP-001 snapshot rejects a UTF-8 BOM at
the beginning of a `.kf` source file.

## Mitigation

Save `.kf` source files as UTF-8 without BOM.

## Impact

Windows editors or scripts that emit UTF-8 BOM may cause otherwise
valid Kof source files to fail during lexical analysis.

## Potential future improvement

The lexer could tolerate an initial UTF-8 BOM, or the required source
encoding could be explicitly documented.
