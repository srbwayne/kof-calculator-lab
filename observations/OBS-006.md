# OBS-006 — Windows packaging fallback requires python3

Category: TOOLING / WINDOWS / PORTABILITY
Status: CONFIRMED + MITIGATED

## Environment

- Windows 11
- Git Bash
- target correctly detected as `windows-x86_64`
- `zip` command unavailable
- Python 3.13.5 installed
- Python available through Windows launcher `py`
- `python3` unavailable

## Relevant packaging behavior

For Windows archive creation, `package.sh` first checks:

    command -v zip

When `zip` is unavailable, it falls back to:

    python3 -c ...

Python is also referenced elsewhere in the packaging script for ZIP
handling.

## Observed failure

The Windows packaging path correctly reached:

    package: version=0.0.7-alpha target=windows-x86_64

but stopped with:

    scripts/package.sh: line 117: python3: command not found

## Controlled mitigation

A temporary wrapper was created outside the Kof repository exposing:

    python3 -> py

The wrapper was added only to the environment PATH for the experimental
execution.

Kof source code and `package.sh` were not modified.

## Result

With the environmental wrapper:

    package: version=0.0.7-alpha target=windows-x86_64
    package: .../kof-0.0.7-alpha-windows-x86_64.zip
    package: .../SHA256SUMS
    package: done

The generated Windows distribution was subsequently validated and
executed successfully.

## Conclusion

A Windows machine can have a functional Python 3 installation while
the packaging fallback still fails because it requires the specific
`python3` command.

## Potential future improvement

Packaging could consider portable Python command discovery and/or
explicitly document the expected Windows dependency.
