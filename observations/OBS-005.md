# OBS-005 — Bash resolution on Windows produces Linux target

Category: TOOLING / WINDOWS / ENVIRONMENT
Status: EXPLAINED

## Context

EXP-001 is being executed on Windows 11.

## Observed environment

PowerShell resolved the generic `bash` command through:

    C:\Users\ojnaa\AppData\Local\Microsoft\WindowsApps\bash.exe

Inside that environment:

    OSTYPE=linux-gnu

and `uname` reported a Microsoft WSL2 Linux environment.

## Observed behavior

Running `package.sh` through that Bash produced:

    target=linux-x86_64

and consequently a Linux distribution.

## Control test

The identical script was executed explicitly with Git Bash:

    C:\Program Files\Git\bin\bash.exe

Result:

    target=windows-x86_64

## Conclusion

Kof target detection behaved correctly for the environment actually
executing the script.

The unexpected Linux target resulted from the generic `bash` command
resolving to WSL rather than Git Bash.

## Impact

A Windows developer with multiple Bash environments may unintentionally
produce a Linux distribution if instructions rely on a generic:

    bash scripts/package.sh

and PATH resolves `bash` to WSL.

## Classification

Not currently considered a defect in Kof target detection.

This is an onboarding/tooling ambiguity involving Bash resolution on
Windows.

## Potential future improvement

Documentation could explicitly identify the expected Windows shell or
provide a native Windows packaging workflow.
