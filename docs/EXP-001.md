# EXP-001 — Kof Calculator Baseline

## Status

`PLANEJADO`

## Origem

Este experimento deriva da:

`IDEA-001 — Kof como sandbox verificável para agentes`

## Objetivo

Construir uma calculadora aritmética mínima em Kof para validar, em um ambiente real e controlado:

* instalação e execução da toolchain Kof;
* compreensão básica da linguagem;
* capacidade de compilar e executar programas simples;
* qualidade dos diagnostics;
* clareza da documentação;
* ergonomia básica da CLI e do fluxo de desenvolvimento;
* estabilidade suficiente para experimentos posteriores com agentes.

Este experimento também servirá como **baseline humano inicial** para futuros experimentos de geração de código por agentes.

## Hipótese experimental

> Se Kof possui maturidade suficiente para servir como ambiente de experimentação com agentes, então um desenvolvedor deverá conseguir implementar, compilar, executar e validar uma calculadora aritmética mínima utilizando documentação e tooling oficiais, com comportamento reproduzível e sem depender de alterações no compilador.

## Escopo

A primeira versão da calculadora deverá suportar somente:

* adição;
* subtração;
* multiplicação;
* divisão.

O comportamento esperado será baseado em dois operandos numéricos e uma operação.

Fluxo conceitual:

`operando A → operação → operando B → resultado`

## Fora de escopo

Não implementar neste experimento:

* interface gráfica;
* aplicação web;
* API HTTP;
* persistência;
* banco de dados;
* histórico de operações;
* autenticação;
* cálculo científico;
* expressões complexas;
* parser matemático próprio;
* precedência de múltiplos operadores;
* integração com Noema;
* integração com LifeOS;
* alterações no compilador Kof;
* fork do Kof4j.

Esses itens só poderão ser considerados em experimentos posteriores.

## Ambiente experimental

Registrar antes da primeira execução:

* sistema operacional;
* arquitetura;
* versão do Java;
* versão do Maven;
* versão do Git;
* versão do Kof/Kof4j;
* commit/tag utilizado do Kof4j;
* backend utilizado;
* versão do VS Code;
* extensões Kof eventualmente utilizadas.

A versão do Kof deverá permanecer congelada durante todo o EXP-001.

Mudanças de versão exigem novo experimento ou registro explícito de desvio.

## Fases

### Fase 0 — Baseline

Antes de instalar ou modificar qualquer componente:

1. registrar ambiente local;
2. identificar a versão exata do Kof que será utilizada;
3. registrar commit/tag do upstream;
4. confirmar que o repositório `kof-calculator-lab` está limpo;
5. criar checkpoint Git.

### Fase 1 — Toolchain

Objetivo:

Confirmar que Kof pode ser instalado ou utilizado de forma reproduzível.

Validar:

* build do Kof4j;
* execução da CLI;
* compilação de um programa mínimo;
* execução do programa mínimo.

Resultado esperado:

`source .kf → compilação → execução`

Qualquer dificuldade deve ser registrada em `observations/`.

### Fase 2 — Hello Kof

Criar o menor programa Kof possível que produza uma saída observável.

Objetivo:

Separar problemas de ambiente de problemas relacionados à calculadora.

Critério de sucesso:

* código compila;
* programa executa;
* resultado é determinístico.

### Fase 3 — Operações aritméticas

Implementar individualmente:

1. soma;
2. subtração;
3. multiplicação;
4. divisão.

As operações devem ser validadas isoladamente antes da composição da calculadora.

### Fase 4 — Calculadora mínima

Combinar as operações em uma única unidade executável.

A calculadora deverá receber ou possuir de forma controlável:

* primeiro operando;
* operador;
* segundo operando.

E produzir:

* resultado da operação;
* comportamento definido para operador inválido;
* comportamento observado para divisão por zero.

O comportamento não deverá ser inventado antes de verificarmos as capacidades reais da linguagem.

### Fase 5 — Casos de teste

Criar casos reproduzíveis em `cases/`.

Conjunto mínimo:

#### Adição

* `2 + 3 = 5`
* `0 + 0 = 0`
* valor negativo + positivo

#### Subtração

* `5 - 3 = 2`
* `3 - 5 = -2`

#### Multiplicação

* `4 * 3 = 12`
* `0 * 10 = 0`
* negativo × positivo

#### Divisão

* `10 / 2 = 5`
* divisão não inteira, se suportada pelo tipo escolhido;
* divisão por zero.

Casos adicionais poderão ser registrados, mas o conjunto mínimo não deve ser removido após o início da execução.

## Observações

Toda dificuldade, surpresa ou comportamento relevante deverá primeiro ser registrada como uma observação.

Formato sugerido:

```text
OBS-XXX
```

Exemplos:

```text
OBS-001 — Diagnostic pouco claro para operador inválido
OBS-002 — Exemplo da documentação diverge da implementação
OBS-003 — CLI oferece feedback suficiente para correção rápida
```

Uma observação pode ser:

* positiva;
* negativa;
* neutra.

O objetivo é produzir evidência, não procurar apenas defeitos.

## Classificação das observações

Quando possível, classificar como:

* `LANGUAGE`
* `COMPILER`
* `RUNTIME`
* `CLI`
* `DOCUMENTATION`
* `TOOLING`
* `EDITOR`
* `EXPERIMENT`
* `USER_ERROR`
* `UNKNOWN`

A classificação inicial pode ser alterada conforme novas evidências surgirem.

## Insight

Uma observação não deve ser automaticamente tratada como melhoria necessária.

Fluxo:

`OBSERVAÇÃO → REPRODUÇÃO → ANÁLISE → INSIGHT`

Um `INSIGHT-XXX` deverá existir somente quando houver evidência suficiente para sustentar uma conclusão útil.

## Possíveis contribuições upstream

Somente depois de um insight validado avaliar:

* melhoria de documentação;
* exemplo adicional;
* issue;
* melhoria de diagnostic;
* melhoria de tooling;
* alteração de código;
* Pull Request.

Nenhuma contribuição upstream faz parte obrigatória do EXP-001.

## Regra de atribuição de falhas

Durante o experimento, uma falha não deve ser atribuída imediatamente ao Kof.

Para cada falha avaliar, nesta ordem:

1. erro no código da calculadora;
2. interpretação incorreta da documentação;
3. ambiente/configuração;
4. uso incorreto da CLI;
5. limitação conhecida;
6. comportamento não documentado;
7. possível defeito da linguagem/toolchain.

Quando não houver evidência suficiente:

`UNKNOWN`

## Critérios de sucesso

O EXP-001 será considerado bem-sucedido se conseguirmos:

1. congelar e registrar uma versão do Kof;
2. reproduzir a instalação/toolchain;
3. compilar um programa Kof mínimo;
4. executar código Kof;
5. implementar as quatro operações;
6. executar a calculadora mínima;
7. validar os casos definidos;
8. registrar observações relevantes;
9. distinguir razoavelmente problemas do experimento de problemas da linguagem/toolchain;
10. produzir evidência suficiente para decidir se Kof é adequado para um primeiro experimento com agentes.

Sucesso não significa ausência de problemas.

Descobrir limitações de maneira reproduzível também é resultado válido.

## Critérios de interrupção

Interromper o experimento antes da implementação completa se ocorrer uma destas condições:

* toolchain não pode ser executada de forma reproduzível;
* versão escolhida apresenta falha impeditiva;
* documentação disponível é insuficiente até mesmo para o programa mínimo;
* comportamento da linguagem é instável a ponto de inviabilizar comparação;
* o experimento exige modificar o compilador para continuar.

Nesse caso, registrar o motivo e decidir entre:

* corrigir o ambiente;
* escolher outra versão;
* criar experimento específico;
* suspender a IDEA-001.

## Regras de congelamento

Depois da primeira implementação da Fase 3:

* não alterar os critérios mínimos de sucesso;
* não remover casos porque falharam;
* não mudar a versão do Kof silenciosamente;
* não alterar resultados anteriores;
* não reinterpretar retroativamente observações sem registrar a mudança.

Novas descobertas devem ser adicionadas como novas evidências.

## Métricas iniciais

Registrar, quando possível:

* tempo até primeiro programa compilado;
* quantidade de erros de compilação encontrados;
* quantidade de consultas à documentação;
* quantidade de tentativas até execução correta;
* número de observações;
* número de problemas reproduzíveis;
* número de insights gerados.

Essas métricas são exploratórias no EXP-001 e ainda não devem ser usadas para comparar agentes.

## Resultado final esperado

Ao encerrar o experimento, produzir:

```text
docs/RESULTS-EXP-001.md
```

O documento deverá registrar:

* ambiente real utilizado;
* versão congelada do Kof;
* implementação final;
* resultados dos casos;
* observações;
* insights;
* limitações;
* desvios do protocolo;
* conclusão.

A conclusão deverá utilizar uma das classificações:

* `GO`
* `GO COM RESSALVAS`
* `NO-GO`

Essa decisão determinará se a IDEA-001 pode avançar para um experimento controlado com agentes.
